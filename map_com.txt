CODING PROFILES SECTION — COMPLETE SPECIFICATION

CONCEPT:
The Coding Profiles section is an original reinterpretation of the tactical/map interface from Resident Evil 4 Remake.

The visitor enters a dark, atmospheric map interface containing several locations/pins. Each location represents one of my coding/developer profiles.

The map should feel like a real interactive navigation system rather than a conventional grid of social links.

The inspiration should be recognizable to Resident Evil 4 players through:
- parchment/map-like visual treatment
- muted earthy colors
- topographic/geographic linework
- location markers
- subtle UI overlays
- directional indicators
- map navigation
- cinematic transitions
- information panels
- tactical/game-like interaction

However, this must be an ORIGINAL implementation.
Do not use ripped RE4 maps, textures, icons, sounds, logos, or other proprietary assets.


==================================================
1. PRIMARY USER FLOW
==================================================

Main Menu
    ↓
CODING PROFILES
    ↓
Map transition / map opening animation
    ↓
Full-screen interactive map
    ↓
User sees profile locations/pins
    ↓
User selects a pin
    ↓
Selected location becomes highlighted
    ↓
Camera smoothly moves/zooms toward the location
    ↓
Profile information panel appears
    ↓
User can:
    - inspect statistics
    - open external profile
    - return to map
    - select another profile


==================================================

==================================================

Initial profiles should support:

- GitHub
- Codeforces
- CodeChef
- LeetCode

- Other coding/developer platforms

    }

==================================================
3. MAP DESIGN
==================================================

The map should occupy most of the viewport.

Desktop:

--------------------------------------------------
| MAP                                  UI PANEL   |
|                                                |
|       ○ GitHub                                 |
|                                                |
|                    ○ Codeforces                |
|                                                |
|                              ○ LeetCode        |
|                                                |
|   ○ CodeChef                                   |
|                                                |
|                           ○ HackerRank         |
|                                                |
--------------------------------------------------

The map should not look like Google Maps.

It should be an illustrated fictional tactical map.

Use:
- irregular terrain
- roads
- paths
- topographic contours
- regions
- rivers
- landmarks
- hand-drawn linework
- subtle grid
- compass
- coordinates
- labels

The locations themselves do not need to correspond to real geography.

The map is metaphorical.

Each coding platform is a "location" in my developer journey.


==================================================
4. MAP VISUAL STYLE
==================================================

Visual characteristics:

- dark parchment
- aged paper
- desaturated brown/green/grey tones
- subtle paper grain
- slightly worn edges
- hand-drawn linework
- subtle vignette
- low-contrast background
- highlighted interactive elements
- cinematic shadows

Do not make the map overly detailed.

The profile pins must remain visually dominant.


==================================================
5. MAP PINS
==================================================

Every profile gets a unique map pin.

Default state:

- subtle
- slightly animated
- low brightness
- recognizable silhouette

Hover state:

- pin becomes brighter
- subtle scale increase
- tooltip appears
- nearby area may slightly illuminate

Selected state:

- stronger glow/highlight
- animated ring/pulse
- platform name appears
- map camera moves toward it

Visited state:

- optionally change appearance slightly so the user knows they have already explored it


==================================================
6. PIN TOOLTIP
==================================================

When hovering over a pin:

--------------------------------
CODEFORCES
Competitive Programming
Rating: 1208
--------------------------------

The tooltip should be compact.

Do not display the entire profile.

Clicking the pin opens the full profile panel.


==================================================
7. CAMERA / MAP MOVEMENT
==================================================

The map should support:

- pan
- zoom in
- zoom out
- reset view
- focus selected location

When a user selects a profile:

1. Current map position is captured.
2. Map smoothly pans toward the selected coordinates.
3. Map optionally zooms in.
4. Pin becomes emphasized.
5. Profile panel appears.

Do not instantly teleport the camera.

Use smooth interpolation.

The animation should feel like moving around a tactical map.

==================================================
19. ANIMATION SYSTEM
==================================================

Entering the Coding Profiles section:

MAIN MENU
    ↓
Screen fades/dims
    ↓
Map surface appears
    ↓
Map expands into viewport
    ↓
Map lines/details reveal progressively
    ↓

The transition should feel like unfolding/opening a tactical map.

Avoid long animations.

Target:
    ~700ms–1500ms for major transitions

==================================================

When nothing is selected:

- paper grain can move slightly

==================================================
24. ACCESSIBILITY
==================================================

The map must not be the ONLY way to access profiles.

Provide an accessible semantic navigation/list.

Every pin must have:
- accessible name
- keyboard focus
- visible focus state
- screen-reader label

Example:

"Codeforces profile, rating 1208"

Keyboard users should be able to navigate every profile without needing a mouse.


==================================================
25. EXTERNAL LINK BEHAVIOR
==================================================

VIEW PROFILE should open the external profile.

Prefer opening external profiles in a new tab.

Use clear external-link indicators.

Do not navigate the portfolio away from the map unnecessarily.


==================================================
26. DATA ARCHITECTURE
==================================================

Profiles must be configuration-driven.

Do NOT write:

if platform === "codeforces"
    render...

throughout the UI.

Instead:

profiles.ts / profiles.json

contains profile data.

The UI renders generic profile objects.

This makes adding a new platform trivial.

Example conceptual structure:

profiles = [
    {
        id,
        platform,
        username,
        url,
        coordinates,
        description,
        category,
        statistics,
        icon,
        featured
    }
]


==================================================
27. STATE MANAGEMENT
==================================================

Keep map state local to the Coding Profiles section unless global navigation genuinely requires it.

State may include:

- selectedProfile
- hoveredProfile
- focusedProfile
- mapPosition
- zoomLevel
- showLegend
- showProfileList

Do not introduce a global state library merely for this section.

Use the simplest appropriate state management solution.


==================================================
28. PERFORMANCE
==================================================

The map should remain performant.

Avoid:
- huge raster images
- excessive DOM nodes
- expensive blur filters everywhere
- constantly running animations
- unnecessary re-renders

Prefer:
- SVG
- CSS
- canvas only where genuinely beneficial
- optimized textures
- GPU-friendly transforms

The map should remain smooth on normal laptops and mobile devices.


==================================================
29. SOUND

Sound is optional.

If implemented:

- subtle map interaction sound
- pin selection sound
- menu navigation sound
- panel opening sound

Use original/licensed sound effects.

Do NOT use extracted Resident Evil 4 sound effects or music.

There should also be a way to disable interface sounds.

The section should feel:

- mysterious
- tactical
- exploratory
- technical
- cinematic
- restrained

It should NOT feel:

- cartoonish
- neon cyberpunk

- overly gamified

32. INFORMATION DENSITY

The map itself should remain visually clean.

Do not place every statistic directly on the map.

The map communicates:

"Where are my profiles?"

The information panel communicates:

"What have I accomplished there?"

Display an in-world message:

[ RETRY ]

"DESTINATION UNAVAILABLE"

[ TRY AGAIN ]

==================================================
38. DESIGN PRINCIPLE

The most important principle:

The map is not decoration.

The map IS the navigation mechanism.

Every visual element should reinforce the idea that my online coding presence consists of different "locations" that the visitor can explore.

The final experience should make the visitor think:

"I am exploring this developer's coding world."

Not:

"This developer put social media icons on a map."
